# Table components — `DataTable`

> Part of the [frontend-components](./SKILL.md) skill.

---

## Purpose

`DataTable` is the framework's table rendering component. It provides a feature-rich, server-driven data grid with:

- **Dynamic columns** from model field metadata
- **Filtering** — auto-generated by field data type (text, numeric, date, choice, reference)
- **Sorting** — click-to-cycle column sort (asc → desc → clear)
- **Pagination** — supports both page-based and cursor-based modes, with page-based pagination as the default
- **Selection** — single or multi-row with callback
- **Toolbar integration** — `tableToolbar` (above) and `rowToolbar` (inline per row)
- **Related field columns** — dot-notation access to 1-to-1 references

**You rarely use `DataTable` directly** — the `@TableView` decorator and `TableViewComponent` handle it. Direct usage is for embedding tables inside `@CustomView` or `@ReadView` nested panels.

## Props overview

`DataTable` accepts either direct props or a single `options` prop built with
`dataTable.options<T>()`. It can also render from an external headless
controller created by `useDataTable`.

```typescript
<DataTable
  ref={tableRef}
  options={dataTable.options<Model>({
    model: 'ModelName',
    columns: [...],
    pagination: { pageSize: 10 },
    defaultSorting: { field: 'createdAt', direction: 'desc' },
    selection: { enabled: true, type: 'multiple' },
    filters: { status: { in: ['active'] } },
    tableToolbar: { buttons: toolbar<Model>({ actions: 'crud' }) },
    rowToolbar: { buttons: toolbar<Model>() },
  })}
/>
```

Controller-driven usage:

```typescript
const controller = useDataTable<Task, 'Task'>({
  model: 'Task',
  columns: [
    { field: 'title', sorting: true, filtering: true },
    { field: 'status', sorting: true },
  ],
  pagination: { pageSize: 10 },
});

<DataTable model="Task" controller={controller} />
```

### Key options

| Option | Type | Description |
| --- | --- | --- |
| `model` | `string` | Model name to query |
| `columns` | `DataTableColumn<T>[]` | Column configuration |
| `pagination` | `{ pageSize: number }` | Items per page |
| `defaultSorting` | `{ field, direction: 'asc' \| 'desc' }` | Default sort applied on first load and when sorting is cleared |
| `initialSort` | `{ field, order: 'asc' \| 'desc' }` | Initial sort for first load only (not reset on sort clear) |
| `selection` | `{ enabled, type }` | Row selection mode |
| `filters` | `object` | Pre-applied filters (static where clause) |
| `tableToolbar` | `{ buttons, alignment? }` | Top toolbar config |
| `rowToolbar` | `{ buttons }` | Per-row inline toolbar |
| `onRowClicked` | `(record) => void` | Row click handler |
| `collapsedFiltersPerRow` | `number` | Override collapsed filter count per row |

### Column configuration

```typescript
interface DataTableColumn<T> {
  field: string; // Field name or dot-notation path
  title?: string; // Override display title
  sorting?: boolean; // Enable column sorting
  filtering?: boolean | FilterConfig; // Enable filtering
  render?: (value, record) => ReactNode; // Custom cell renderer
}
```

### Toolbar alignment

```typescript
tableToolbar: {
  alignment: 'left',  // 'left' or 'right' (default: 'right')
  buttons: toolbar<Model>({ actions: 'crud' }),
}
```

- `'right'` (default): Uses ProTable's `toolBarRender` (right-aligned)
- `'left'`: Uses ProTable's `toolbar.title` prop (left-aligned)

## `DataTableRef` — imperative API

```typescript
const tableRef = useRef<DataTableRef>(null);

// Refresh table data
tableRef.current?.refresh();

// Clear current selection
tableRef.current?.clearSelection();

// Open another view
tableRef.current?.openView(ViewClass, { params: { id: 'record-id' } });

// Read object actions from the first loaded row
const actions = tableRef.current?.getObjectActions();
```

`DataTableRef` no longer exposes a generic `getTableState()` snapshot. If you
need direct access to rows, filters, sorting, pagination, and metadata, use the
headless `useDataTable` controller instead.

## Headless controller — `useDataTable`

Use `useDataTable` when `DataTable` is only one possible renderer for the same
state.

Common examples:

- switch a card between `DataTable` and `ProList`
- keep framework filtering/sorting/pagination while loading from a custom
  service via `loadData`
- read metadata-aware values with `controller.getUiRecord(record)` and render
  them through `DataComponent`

Detailed hook guidance lives in
[frontend-hooks/useDataTable.md](../frontend-hooks/useDataTable.md).

## Related field columns (dot notation)

Access fields from 1-to-1 references:

```typescript
columns: [
  { field: 'project', sorting: true, filtering: true },
  { field: 'project.name', sorting: true, filtering: true },
  { field: 'project.code', sorting: true },
];
```

**Requirements:**

- Root field must be a single (1-to-1) reference
- Array relationships are not supported
- TypeScript autocomplete via `NestedKeyOf<T>`

## Examples

### Embedded `DataTable` in `CustomView`

```typescript
import { DataTable, dataTable, toolbar } from '@drumr/framework-frontend';
import type { DataTableRef } from '@drumr/framework-frontend';

tableRef = createRef<DataTableRef>();

override onRender(): React.ReactNode {
  return (
    <DataTable
      ref={this.tableRef}
      options={dataTable.options<Task>({
        model: 'Task',
        columns: [
          { field: 'number', sorting: true },
          { field: 'title', sorting: true, filtering: true },
          { field: 'assignee', filtering: true },
          { field: 'status', sorting: true, filtering: true },
        ],
        pagination: { pageSize: 10 },
        selection: { enabled: true, type: 'multiple' },
        rowToolbar: {
          buttons: toolbar<Task>(),
        },
        filters: {
          status: { in: ['to_do', 'in_progress', 'in_review'] },
        },
      })}
    />
  );
}
```

### Table via `@TableView` decorator

The `TableViewComponent` renders DataTable internally from `tableOptions`:

```typescript
import { TableView, TableViewComponent, TableViewTableOptions, toolbar } from '@drumr/framework-frontend';

@TableView({
  path: '/locations',
  model: 'Location',
})
export default class LocationTableView extends TableViewComponent<Location> {
  override tableOptions: TableViewTableOptions<Location> = {
    columns: [
      { field: 'name', sorting: true, filtering: true },
      { field: 'state', sorting: true, filtering: true },
      { field: 'county', sorting: true, filtering: true },
      { field: 'city', sorting: true, filtering: true },
    ],
    pagination: { pageSize: 10 },
    selection: { enabled: true, type: 'multiple' },
    rowToolbar: {
      buttons: toolbar<Location>(),
    },
  };

  override onRowClick(location: Location): void {
    this.openView(LocationEditView, {
      container: 'current',
      params: { id: location.id },
    });
  }
}
```

### Multiple `DataTableRef` in dashboard (project-management-app)

```typescript
// apps/project-management-app/frontend/src/dashboard/views/SummaryView.tsx
import { DataTable, toolbar } from '@drumr/framework-frontend';
import type { DataTableRef } from '@drumr/framework-frontend';

private readonly projectTableRef = React.createRef<DataTableRef>();
private readonly taskTableRef = React.createRef<DataTableRef>();

// Each table can be independently refreshed
this.projectTableRef.current?.refresh();
this.taskTableRef.current?.refresh();
```

## Best practices

1. **Prefer `@TableView` over direct DataTable** — use `tableOptions` in the class-based view for standard CRUD tables.
2. **Use direct DataTable only in custom views** — dashboards, nested panels, or read views with embedded tables.
3. **Always type `dataTable.options<Model>()`** — provides full column field autocomplete.
4. **Use `filters`** for pre-applied conditions that the user cannot remove.
5. **Use `toolbar<T>({ actions: 'crud' })`** for `tableToolbar` to get only create/delete buttons.
6. **Use `toolbar<T>()`** for `rowToolbar` to auto-generate all available object actions.
